Technical Architecture • Hybrid Philosophy

Hybrid Architecture: "AI Proposes, Deterministic CRE Executes"

Why LLMs must never directly write unverified data to production medical records, and how our hybrid engine guarantees safety, compliance, and speed.

🏛️ Core Philosophy & Why Pure LLM Fails in Healthcare
⚠️ The Danger of Unrestricted LLMs in Clinical Systems:

LLMs are non-deterministic. If an AI model hallucinates a patient birth date, drug dosage, or MRN, it introduces medical malpractice and HIPAA compliance liability.

Our 3-Layer Hybrid Separation of Concerns:

  1. Cognitive Layer (Google Gemini): Used exclusively to read unfamiliar schemas, reason across clinical terminology, and propose candidate mapping rules.
  2. Human Governance Gate: AI proposals are strictly tagged pending_review. A human operator must visually verify and cryptographically sign off.
  3. Deterministic Execution Core (CRE): Record transformation is executed by audited Python code and validated against official Pydantic FHIR R4B schemas.
🔄 Complete End-to-End System Topology
1. Source Ingestion Layer:

Extracts from HAPI FHIR R4, EHR feeds, or user files (CSV, TSV, JSON, Excel .xlsx with serial dates).

2. Cognitive AI Reasoning Layer (Gemini 3.5 Flash):

Synthesizes MappingConfig JSON with confidence scores, clinical rationales, and Zero-Data-Loss extensions.

3. Human-in-the-Loop Governance Gate:

Interactive UI approval gate. No unapproved mapping contract can ever execute in production.

4. Deterministic Core Rules Engine (CRE) & Medplum:

Transforms records, enforces Pydantic schemas, auto-heals errors, and conditionally upserts into Medplum PostgreSQL.

Core Architectural Breakthroughs in Our Platform

Three critical engineering features that prevent data corruption, maintain relational links, and ensure corporate security.

1. Dual-Layer Deduplication & Idempotency

Code Reference: app/pipeline.py & medplum.py

  • Layer 1 (In-Batch): In-memory seen_ids tracker skips duplicate records within the active ingestion stream.
  • Layer 2 (Destination DB): Conditional upsert via PUT /Patient?identifier=urn:source:sys|id.

2. Auto-Parent Patient Resolution

Code Reference: app/pipeline.py

  • Clinical resources (Observation, Condition, Encounter) reference parent patients.
  • If a parent Patient does not exist in Medplum, our pipeline automatically queries HAPI FHIR, fetches the parent, and ingests it first.
  • Guarantees zero orphaned clinical resources and preserves 100% relational integrity.

Code Reference: app/mapping/suggest.py

  • Corporate healthcare networks use SSL inspection proxies that break default Python certifi bundles.
  • Our platform integrates Python truststore, injecting Windows/OS native CA certificates into HTTPX.
  • Flawless enterprise network execution with zero insecure SSL verification workarounds.

A: Yes. The platform uses memory-efficient streaming, SSE chunking, and adaptive micro-pacing, running smoothly in Docker on commodity hardware or Kubernetes.

Enterprise Resilience • Edge Case Handling

Enterprise Edge-Case Defense: HTTP 429 & Excel Serial Dates

How our platform conquers real-world hospital data problems: Medplum's 50,000-point rate ceiling and Microsoft Excel OpenXML numeric date formats.

1. Dynamic HTTP 429 Rate Limiter Defense (app/connectors/http.py)

During a 650-record streaming test, Medplum's built-in Valkey rate limiter breached its 50,000-point window at record #640, throwing HTTP 429 Too Many Requests.

Diagnostics: {"_remainingPoints": 0, "_msBeforeNext": 36022, "limit": 50000}

Our connector dynamically parses _msBeforeNext (36.022s) and Retry-After, sleeping precisely until the token bucket resets. Zero failed records.

2. Native Excel OpenXML Serial Date Ingestion (engine.py)

Excel workbooks (.xlsx) store dates as floating-point day offsets since December 30, 1899 rather than standard text strings.

  • Serial 39216 = 1899-12-30 + 39,216 days = 2007-05-14
  • Serial 18476 = 1899-12-30 + 18,476 days = 1950-08-01

normalize_fhir_datetime() auto-detects numeric serial days (1 to 100,000) and transforms them into ISO YYYY-MM-DD. Prevents 100% of batch quarantines.
